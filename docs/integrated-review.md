Independent pre-publication review of the C# implementation. No unresolved blocking defect remains in the reviewed source snapshot. Executed evidence is distinguished from checks that the reviewer did not run.

2026-10-03、実装担当とは別のレビュアーが、ライブラリを読み、専用の依存なしテストを追加し、統合テストも実行しました。レビュアーは実行時のソースを直接変更していません。指摘は担当者が修正しました。

対象スナップショットの 21 個のソース・設定ファイルの SHA-256 は [review-evidence.json](review-evidence.json) に記録しています。相対パスから作った集合識別子は `ffdf35d9e1ef59bde59566a77639f0dd8ce184e8e1c1cf11dacba0c489b85e62` です。記録スクリプトは検証前後のソースハッシュが変わっていないことを確認します。ドキュメント変更だけではこの識別子は変わりません。

最終統合記録 [core-local.json](evidence/core-local.json) と、ライブラリの全 17 C# ソースハッシュ、両フレームワークの実行アセンブリハッシュが一致することも照合しました。

## 修正済みの指摘

1. **Digital Link の dot-segment による値の消失。** AI 10 の値 `..` をパスに置くと、URL 正規化が AI と値を除去しました。`.` は不正な AI と値のパスを作りました。基準 JavaScript にも存在する問題を実際に再現しました。C# は選択されたパス値が `.` / `..` の場合に拒否し、`PathAis = []` でクエリに置いた値は保持します。リテラル `%2e` は通常データとして保持します。2 個の該当 fixture は意図的な差分として明示しています。
2. **Structured Append 適合性テストの設定誤り。** テストがテキスト・バイナリ入力にも手動入力専用の Full 分割単位詳細を指定していたため、正しい実行時検証によって停止しました。Full は手動入力の fixture のみに指定するよう修正され、最終の SA グループは両対象で成功しました。

高水準 GS1/FNC1 のリテラル `%` を Byte モードで保持する既存の安全性修正も確認しました。安全でない Alphanumeric の明示指定は拒否し、低水準 FNC1 セグメントの `%` / `%%` エスケープは呼び出し側が管理します。

スキップは両対象とも 0 です。GS1 グループは 1,411 件の基準 fixture と追加検証を含みます。上の統合グループの件数はハーネスが報告するケース・検査単位で、全内部アサーション数を意味しません。

レビュアー用実行プログラムは特に次を検証します。

- 80 件の決定的な混在 Unicode SA 入力を V1/2/4/9/10/26/27/40 と最適化の有効・無効で生成し、全分割片のビット長を公開 `Estimate` と照合。次のスカラーを一つ追加すると容量を超えることを検証し、容量内に収まる最大の接頭部を確認。
- V1-L の単一モードの境界: 数字 35 桁、Alphanumeric 21 文字、15 バイト、Kanji 9 スカラー。分割数と各分割片の長さを確認。
- 300 バイトの手動セグメントが V2-L で 30 bytes × 10 symbols に分割できること。分割前の 8 bit の文字数フィールド上限で誤って拒否しないこと。summary は単位一覧を保持せず、full と生成コードワードが一致すること。
- セグメントの入出力、行列の各行、データ・インターリーブ後のコードワードの防御的コピー、32 並行生成、FNC1 のリテラルパーセントの両形態と最適化の有効・無効。
- `.` / `..` のパス拒否とクエリの往復変換。描画の配置・寸法の整数境界、ラスタ上限、不正な色・XML・DPI の拒否、不正な設定では出力ストリームに一切書かないこと、SVG タイトルのエスケープ、不正な SA ヘッダーの getter の安全性。

再実行:

```sh
python3 tools/review/run.py --dotnet dotnet --output artifacts/review-evidence.json
```

このスクリプトはパッケージソースを追加せず、両フレームワークをビルドして実際の実行ファイルを起動します。sandbox のコンパイラーサーバーの IPC に依存しないよう、ビルドサーバーと共有コンパイルを無効にしています。

## ソース確認の範囲

QR のテーブル、GF(256)/Reed–Solomon、インターリーブ、機能・データモジュールの配置、マスクのスコア計算と同点時の選択、セグメント・制御の検証、文字数ビット幅の区分、計画の事前検査、GS1 カタログ・URL adapter、SA の追跡・マージ、移植可能な描画処理を確認しました。共有テーブルは公開されず、エンコーダーの作業状態は呼び出しごとです。PNG は BCL zlib と独自のフレーム構築・CRC、SVG は限定した色形式と XML エスケープを使用します。

`PackageReference`、第三者 QR ランタイムの呼び出し、`System.Drawing` 依存はライブラリ内にありません。依存なし・MIT・ユーザー所有の基準実装と開発用 oracle の区別は [provenance](provenance.md) に記載されています。最終依存監査と外部デコーダーの実行記録は [verification](verification.md) を参照してください。

## このレビューの限界

このレビュアーは Windows/Linux での実行、GitHub CI、外部デコーダー、物理カメラ・印刷試験を実行していません。これらを上表の成功に含めません。公開にあたっての実 CI、外部 oracle・デコーダー、隔離した環境の利用側プログラム、公開コミットの一致は [verification](verification.md) に分けて記録します。

URL 補助機能は範囲を限定した SpecQR の契約であり、ブラウザ URL API 全体や GS1 全仕様の認証ではありません。低水準 FNC1 のエスケープ、Unicode/ECI の責務、資源上限、対象外プラットフォームはそれぞれの API 文書に従います。このレビューは検査したスナップショットに対する結果であり、将来の変更や全入力に対する無欠陥の証明ではありません。
